Hardware Overview

The HAR Distributed Framework was implemented using a heterogeneous hardware architecture composed of wearable sensing devices, embedded edge computing platforms, a central computing node, and a dedicated wireless communication network.

The hardware infrastructure supports the complete distributed Human Activity Recognition (HAR) pipeline, including sensor acquisition, local neural network inference, inter-node communication, central prediction fusion, experiment logging, and real-time visualization.

Hardware Architecture

The physical implementation of the framework can be divided into four main hardware groups:

  1. Wearable sensing devices
  2. Edge computing nodes
  3. Central computing node
  4. Network infrastructure

The general hardware organization is:

The wearable sensors capture body motion at different anatomical locations. Each sensor communicates with an associated embedded edge computer, where sensor-specific processing and local HAR inference are performed.

The resulting predictions are transmitted through the local wireless network to the central computing platform.

Wearable Sensors

The sensing layer of the framework uses MbientLab MetaMotionRL wearable devices.

The devices used in the experimental system correspond to the MetaMotionRL r0.5 platform.

These wearable sensors provide inertial and orientation measurements that can be used to characterize human movement.

The distributed configuration uses five body locations:

Sensor Node Body Location
Chest Chest
Left Hand Left hand
Right Hand Right hand
Left Knee Left knee
Right Knee Right knee

The placement of sensors at different body locations provides complementary information about upper-body, lower-body, and torso motion.

Sensor Modalities

Depending on the sensing node and experimental configuration, the framework uses inertial or orientation information.

The primary signal representations used throughout the project include:

  • accelerometer measurements;
  • gyroscope measurements; and
  • quaternion-based orientation measurements.

Accelerometer and gyroscope streams can be represented as:

ax, ay, az, gx, gy, gz

while quaternion orientation is represented as:

w, x, y, z

The exact signal configuration used by each model is described later in the data acquisition and model development sections.

Sensor Communication

Each wearable sensing device communicates wirelessly with its corresponding edge computing node.

The wearable-to-edge connection is based on Bluetooth Low Energy (BLE).

This creates the first communication stage of the distributed architecture:

MetaMotionRL
     │
     │ BLE
     ▼
Edge Computing Node

Sensor acquisition therefore occurs locally at each embedded computing node before any information is exchanged through the distributed network.

Edge Computing Nodes

The distributed processing layer is implemented using NVIDIA Jetson embedded computing platforms.

The framework has been developed and evaluated using devices from the Jetson family, including:

  • NVIDIA Jetson Nano
  • NVIDIA Jetson Orin Nano

Each edge node is responsible for the processing associated with one wearable sensor stream.

Edge Node Responsibilities

The primary responsibilities of each embedded edge device include:

  • establishing communication with the wearable sensor;
  • acquiring incoming sensor measurements;
  • buffering sensor samples;
  • constructing model input windows;
  • preprocessing data when required;
  • executing the local HAR neural network;
  • generating activity probability vectors;
  • timestamping local predictions;
  • publishing predictions to the communication network; and
  • recording local timing information when required.

The local processing pipeline can therefore be summarized as:

Local Input Window

The real-time inference pipeline operates using windows containing 50 samples.

At a nominal acquisition rate of 50 Hz, a complete 50-sample input window represents approximately:

50 samples / 50 samples per second = 1 second

of sensor information.

Once the required number of samples is available, the local model performs inference and generates the corresponding class probability vector.

Central Computing Node

A separate NVIDIA embedded computing platform acts as the central node of the distributed framework.

The primary central platform used for the distributed real-time system is the:

NVIDIA Jetson AGX Xavier

Unlike the edge nodes, the central computing node does not directly perform the sensor-specific local classification tasks.

Instead, it receives the outputs generated by the distributed classifiers and performs system-level processing.

Central Node Responsibilities

The central node is responsible for:

  • receiving local prediction messages;
  • managing predictions from multiple edge devices;
  • temporally synchronizing distributed predictions;
  • detecting missing or delayed inputs;
  • applying fallback mechanisms when required;
  • executing the central fusion model;
  • generating the global HAR prediction;
  • recording communication and synchronization metrics;
  • recording inference and end-to-end timing information; and
  • transmitting results to the visualization interface.

Network Infrastructure

Communication between the embedded computing nodes is performed through a dedicated wireless local area network.

The experimental framework uses a:

Ubiquiti Dream Router 7

as the central network infrastructure connecting the distributed Jetson devices.

The network supports communication between:

  • the five distributed edge nodes;
  • the central computing node; and
  • additional systems involved in monitoring or visualization when required.

The overall communication structure is:

Edge Node 1 ──┐
Edge Node 2 ──┤
Edge Node 3 ──┤
Edge Node 4 ──┤──► Wi-Fi Router ◄──► Central Node
Edge Node 5 ──┘

A dedicated local network reduces dependence on external network infrastructure and provides a controlled environment for measuring communication behavior.

The detailed IP configuration, ROS networking configuration, and communication protocol are described later in the documentation.

Hardware Summary

The distributed framework uses a physically distributed architecture consisting of:

  • 5 MetaMotionRL wearable sensors;
  • 5 embedded edge computing nodes;
  • 1 central NVIDIA Jetson AGX Xavier; and
  • 1 dedicated wireless router.

The resulting system contains six embedded computing devices participating in the inference architecture:

5 Edge Computing Nodes
          +
1 Central Computing Node
          =
6 Embedded Computing Nodes

The five edge devices perform local sensor-level inference, while the central device performs synchronization and prediction fusion.

This hardware organization provides the physical foundation for the distributed processing strategy described in the System Overview.
