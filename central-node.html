Central Node

Synchronization, Fusion, and Global Prediction

The central node performs the system-level processing of the HAR Distributed Framework.

It receives the local predictions generated by the five edge nodes, coordinates them temporally, executes the central fusion model, and produces the final global Human Activity Recognition prediction.

The central node also supports experiment logging and communication with the visualization interface.

Central Processing Pipeline

The main processing stages executed by the central node are summarized in Figure 1.

The central pipeline consists of four main stages:

  1. Prediction Reception
  2. Temporal Synchronization
  3. Central Fusion
  4. Global Prediction Generation

Logging and visualization operate as downstream consumers of the system output.

Prediction Reception

Each edge node publishes the probability distribution generated by its local HAR model.

The central node receives predictions from the five sensing locations:

  • Chest
  • Left Hand
  • Right Hand
  • Left Knee
  • Right Knee

The received messages contain the information required by the central processing pipeline, including the local probability vector and associated metadata.

The exact ROS topics, message structure, timestamps, and sequence fields are documented under Communication & Synchronization.

Temporal Coordination

Predictions are generated independently by the distributed edge nodes.

As a result, the central node must coordinate the incoming messages before they are provided to the fusion model.

This stage ensures that the local predictions used together correspond as closely as possible to the same time interval.

The central implementation also includes mechanisms for maintaining operation when one or more predictions are temporarily delayed or unavailable.

Detailed synchronization behavior is documented under Communication & Synchronization.

Central Fusion

Once a compatible set of local predictions is available, the central node combines them and provides the resulting input to the fusion model.

The fusion model receives information from all five local classifiers and produces a system-level probability distribution over the supported activities.

The central node therefore performs a different role from the edge devices:

Processing Level Function
Edge Nodes Sensor-level inference
Central Node Prediction-level fusion

The detailed fusion-model architecture, input organization, and trained model files are documented under Models & Data.

Global Prediction

The fusion model generates a probability distribution representing the final HAR output.

The system selects the resulting global activity prediction from this distribution.

The global output can then be consumed by:

  • Experiment Logging
  • Performance Measurement Tools
  • The Real-Time Visualization Interface

The execution workflow is documented later under Running the Framework.

Experiment Logging

The central node records information required to evaluate the real-time behavior of the distributed system.

Depending on the experiment, the recorded information includes:

  • Local Prediction Information
  • Global Predictions
  • Synchronization Measurements
  • Communication Timing
  • Central Processing Timing
  • End-To-End System Timing

The exact log files, fields, and analysis workflow are documented under Experiments & Logs.

Visualization Output

The global prediction is also made available to the visualization layer.

In the implemented system, this output can be consumed by the Unity-based graphical interface used to display the recognized activity during real-time execution.

The visualization procedure is documented as part of Running the Framework.

Central Node Responsibilities

The implementation of the central node can be summarized as:

Responsibility Description
Prediction reception Receive local outputs from the five edge nodes
Synchronization Coordinate independently generated predictions
Fusion Execute the central prediction model
Global inference Generate the system-level HAR output
Logging Record real-time experiment measurements
Visualization output Provide global predictions to the user interface

Verification

Before running a complete experiment, verify the central node incrementally.

Confirm that:

  • The ROS environment is available
  • The central node can receive local prediction messages
  • Predictions from all five edge nodes are visible
  • Synchronization is operating correctly
  • The fusion model loads successfully
  • A valid global probability vector is generated
  • The global prediction is published
  • Logging is active when required
Tip

Verify prediction reception before troubleshooting the fusion model.

If one or more edge streams are missing, the problem may originate in the distributed communication layer rather than the central inference component.

Troubleshooting

One or More Edge Predictions Are Missing

Verify the corresponding edge node first.

Confirm that:

  • Local inference is running;
  • A valid probability vector is being generated; and
  • The local prediction is being published.

Then verify the communication configuration under Communication & Synchronization.

Fusion Model Does Not Load

Verify that:

  • The expected model file is available
  • The configured model path is correct
  • PyTorch can load the model
  • The model definition matches the saved parameters
  • The runtime environment is compatible

Detailed model information is documented under Models & Data.

Local Predictions Arrive but No Global Prediction Is Generated

Check whether the central synchronization stage is producing a valid set of inputs for fusion.

If the incoming predictions are available but cannot be combined, continue with Communication & Synchronization.

Logging Is Not Generated

Verify that:

  • The logging component is enabled
  • The output directory exists
  • Sufficient storage is available
  • The process has permission to write to the configured location

Log organization is documented under Experiments & Logs.
